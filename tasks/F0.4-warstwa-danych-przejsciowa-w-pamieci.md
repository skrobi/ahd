# F0.4 Warstwa danych przejściowa (w pamięci)

- **Status:** zrobione
- **Moduł:** Shared
- **Zależy od:** F0.2
- **Otwarte kwestie:** –

## Cel

Moduły pracują na „bazie w pamięci” o kształcie docelowego schematu MS SQL; przejście na bazę zmienia tylko implementacje magazynów.

## Wymagania

- `InMemoryDatabase`: nazwane tabele (`meta.*`, `stg.*`, `can.*`, `dict.*`) z typami wierszy w `Shared/Models/Db` (schemat wspólny jak w bazie).
- Operacje zapisu atomowe (blokada; walidacja przed zmianą danych).
- Zapis i odczyt stanu do pliku JSON (`InMemoryStatePath`) – dane przetrwają restart aplikacji; brak pliku = dane startowe (seed).
- `IClock` (czas testowalny), generator identyfikatorów.
- Każdy moduł: `Data/I<Moduł>Store` (kontrakt = przyszłe procedury i widoki) + `Data/InMemory<Moduł>Store`.

## Poza zakresem

- implementacja SQL (F10)
- współdzielenie stanu między stanowiskami (tryb w pamięci jest lokalny)

## Kryteria akceptacji

- [x] Test: zapis → odczyt stanu z pliku daje te same dane.
- [x] Test: zapis odrzucony przez walidację nie zmienia danych.
