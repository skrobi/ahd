# F2.2 Import plików (G1)

- **Status:** zrobione
- **Moduł:** Import
- **Zależy od:** F2.1, F0.7
- **Otwarte kwestie:** O29, O31

## Cel

Każda nowa wersja raportu RABIT trafia do bazy jako wiersze surowe z pochodzeniem.

## Wymagania

- Wejście: wszystkie aktywne lokalizacje i folder `<NetworkRoot>\00_Global\RABIT\Do_importu`; pliki `~$*`, ukryte i `.part` pomijane.
- Decyzja dla pliku: **pominięty** (te same metadane: lokalizacja, nazwa, rozmiar, data modyfikacji – i treść pliku jest w bazie), **nierozpoznany** (brak prefiksu – WARNING), **duplikat** (ten sam SHA-256 – kto i kiedy go zaimportował), **zaimportowany**, **błąd**.
- Najdłuższy pasujący prefiks wygrywa; plik identyfikuje lokalizacja + nazwa.
- Zaimportowany: wersja pliku (`meta.SourceFile`: hash, lokalizacja, nazwa, kod źródła, data modyfikacji, kolumny, sygnatura, liczba wierszy), wiersze surowe (`stg.RawRow`; od migracji 008 plik nie jest przechowywany – dane w `can.Row`), wpis w `meta.SourceFileSeen`, partia importu (`meta.ImportBatch`: kto, komputer, wersja, liczniki).
- Błąd pliku albo niedostępna lokalizacja (ERROR) nie zatrzymuje pozostałych.
- Operacja długa: postęp i anulowanie – status pliku pokazuje etap (pobieranie na dysk, sprawdzanie, odczyt i zapis wierszy, kontrola w bazie) z postępem i czasem; anulowanie także w trakcie pliku (zapis wycofany); zakleszczenie w bazie (1205) – zapis pliku powtarzany do 3 razy.
